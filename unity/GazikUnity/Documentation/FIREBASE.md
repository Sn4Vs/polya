# Прежний Firebase и безопасность прогресса

Используется существующий проект `zametki-79427` и документ `pets/zvezdochka-hedgehog`. Нового Firebase-проекта нет. Публичные настройки клиента взяты из прежнего сайта; секреты и административные ключи не добавлялись.

`GazikMobile/cloud.js` разрешает загрузку только двум прежним UID. Владелец получает роль owner, второй аккаунт — viewer. Восстановление разрешённого сеанса выполняется после готовности Unity; без него остаётся локальная игра. HTML-форма входа доступна через «Облако», и Unity не захватывает её клавиатуру.

Перед записью читается серверное состояние. Транзакция сравнивает timestamp и отпечаток всего документа, поэтому одинаковый timestamp не скрывает параллельное изменение. Сохранения идут последовательно. Выход, смена аккаунта, конфликт или ошибка отзывают право записи. Живые обновления не запускают повторную запись сами по себе. Неизвестные поля и вложенные поля сохраняются.

Локальное сохранение и облачная копия разделены. Возврат в локальный режим возвращает собственную локальную игру. Импорт JSON доступен локально и сохраняет копию до импорта. Автоматические тесты не выполняют вход и не записывают настоящий документ.

## Что должно быть проверено на сервере

Клиентские ограничения не заменяют Firestore Security Rules. Для этого документа чтение должно разрешаться прежним владельцу и наблюдателю, запись — владельцу, посторонним — отказываться. Реальные опубликованные правила в этой сессии не прочитаны и не изменены: нет подтверждённого административного Firebase-сеанса. Правила других разделов романтического сайта заменять нельзя.

Перед выпуском: экспортировать резервную копию, открыть новый WebGL тем же владельцем, сравнить имя/звёзды/письма/покупки, завершить один уход и проверить серверную запись; затем открыть наблюдателем и проверить отсутствие изменений. Отдельно проверить отказ постороннему аккаунту и конфликт двух устройств. Это живые проверки; mocked Firebase-тесты их не подменяют.
