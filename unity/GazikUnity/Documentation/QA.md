## Условия автоматических проверок

Native QA использует отдельную копию проекта и хранилище в памяти. Настоящие PlayerPrefs и Firebase-прогресс не изменяются. Покупки проверяются на временном состоянии, после чего оно восстанавливается. Проверки взаимодействий идут по кадрам: подход → готовность → настоящий raycast по 3D-цели или drag через экранную проекцию → завершение → ровно одна награда.

Снимки и отчёты разделены по портретному/горизонтальному запуску. `Check-And-Build.ps1` дополнительно требует успешный native-отчёт и успешный результат Unity BuildPipeline. Сырые журналы редактора, сведения лицензии, Library и пользовательские сохранения в исходный архив не включаются.

## Ещё не подтверждено

- Полный WebGL-сеанс в браузере, его консоль, HTML-вход, клавиатура, drag/touch и звук. Ранее браузерный инструмент блокировал локальный origin сохранённой политикой; разрешение пользователя само по себе этот запрет не сняло.
- Настоящие Firebase-аккаунты владельца/наблюдателя, серверные Security Rules и перенос живого прогресса. Тесты bridge работают с имитацией и не касаются сервера.
- Chrome Android и Safari iPhone на физических устройствах: FPS, память, нагрев, загрузка, фон/возврат, экранная клавиатура и safe-area.

Эти ограничения не выдаются за пройденные проверки. Работоспособность в Unity и успешный WebGL build сами по себе не доказывают совместимость каждого телефона.

## Воспроизведение

`Tests/Run-Checks.ps1` запускает Core/каталог/JavaScript. `Check-And-Build.ps1 -UnityPath ...` запускает реальные Play Mode и WebGL. В Editor доступны меню Gazik и команда создания настоящего скриншота. Для проверок и сборки исходник должен находиться в отдельной копии, если основной проект уже открыт редактором.
